SSL certificate checker: when does this site’s certificate expire?

Enter a domain and the free check opens a real TLS connection to it, reads the certificate the server presents and shows the expiry date with the number of days left. A certificate with 30 days or fewer is flagged.

Check a certificate now

Free and without an account. The result opens on the next page, together with the site’s security headers, SPF and DMARC records and public files.

What the check reads

The certificate comes from a live TLS handshake with the domain you enter, the same exchange a browser performs before it shows a page. The result is the certificate’s expiry date (its notAfter field) and the whole days left from now. An expired certificate is shown with the date it stopped being valid.

The flag at 30 days is the same threshold the full scan treats as late, so the free result and a client report never disagree about the same certificate. The full scan then raises the severity again at 14 and at 7 days.

What one check does not prove

  • It reads the host you enter and does not follow redirects. If visitors land on www or on another host, check that one too.
  • It covers one certificate. Subdomains, mail servers and APIs can have their own, with their own dates.
  • A CDN or proxy in front of the site presents its own certificate, and that is the one the check reads.
  • The free check reports the expiry date. Who issued the certificate, which names it covers and whether it signed itself are reported by the full scan on a verified domain.

When the date is close

  1. Find what renews the certificate: a hosting panel, a CDN, or an ACME client such as Certbot running on the server.
  2. Check that it last succeeded. Automatic renewal fails quietly when the DNS or HTTP validation it relies on has moved.
  3. After renewing, make sure the server serves the new certificate: some need a reload before they present it.
  4. Run the check again and confirm the new date.
